## 测试配置

- 数据：比赛提供的真实TLE、站址和优先级文件
- 时间：2026-10-01 00:00:00 UTC 至 2026-10-07 00:00:00 UTC
- 活跃目标：按数据加载顺序截取前100颗卫星
- 活跃站点：前3个观测站
- 规划器：方案G（AI候选筛选 + CP-SAT + 候选回流 + 局部搜索）
- 可见窗口：强制重新计算，未使用旧缓存

运行命令：

```powershell
.venv\Scripts\python.exe -m observation_system run `
  --config observation_system\config\default.json `
  --planner scheme_g `
  --limit-targets 100 `
  --limit-stations 3 `
  --output-dir outputs\stress_100x3 `
  --force-windows
```

## 结论

该规模下完整链路运行成功。方案G覆盖了全部60颗在当前站点集合和约束下具备合法窗口的卫星，AI安全筛选将候选规模压缩83.45%，CP-SAT得到最优状态，独立校验未发现站内冲突、30秒转换冲突、48小时重复观测冲突或窗口越界。

规划阶段总耗时明显高于CP-SAT内部求解时间，说明下一档压力测试应重点监控候选筛选、冲突构建、候选回流和局部搜索，而不能只关注求解器耗时。
