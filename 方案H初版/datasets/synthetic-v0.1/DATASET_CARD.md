# 空间目标观测调度合成数据集 synthetic-v0.1

本数据集服务于**地面观测站对空间目标的观测任务规划**。输入是合成目标轨道、观测站、时间范围、优先级及观测规则；输出包括可见窗口、候选任务特征、本地教师的网格选择标签，以及按整数秒精修后的完整计划。

本版本是**采用候选短表的低成本教师示范数据集**：每个目标最多保留 12 个窗口，由这些窗口生成候选，可供训练排序模型。完整几何窗口仍随 catalog 保存，便于以后扩大候选池。它不是全窗口搜索结果、实际卫星观测记录或人工专家标注，也没有最优性证明。以下设计在批量生成前锁定；本页实际数量已由完整生产清单和通过的审计报告回填，设计与实测分列记录。

生成代码冻结提交为 **`85bc712b3035b103dfd72adaaa90e578002b043e`**。正式生产使用 4 个窗口进程；一个 catalog 的窗口生成结束后，再用 4 个独立 scene 进程生成四变体，每个 scene 的 Numba/BLAS 线程固定为 1。窗口进程与 scene 进程不会同时运行。冻结协议正文保留了早期串行设计，实际并行配置及生成身份以本次 `manifest.json.identity` 与这里的记录为准；正式数据和之前串行试跑的记录分开保留。

## 如何生成一个场景

1. 按上述轨道分布和随机种子生成目标的平均轨道要素。种子为 `2026110700 + catalog_index`，起始日期为 `2026-01-10 + (37 × catalog_index mod 330) 天`，历元位于六天规划期中点。先用 WGS72 参数初始化 SGP4，再导出 TLE、检查校验和并回读；正式传播使用回读后的 TLE，避免发布数据与内存轨道不同。每颗目标在历元处检查传播返回码及位置/速度有限性，窗口生成时继续保留传播失败状态。
2. 给 catalog 赋予站点配置和目标优先级，形成下表四个变体。变体增加资源及价值分布差异，不复制同一计划冒充新监督。目标名以 `SYN-` 开头；TLE 的 `satnum` 从 10001 起，在不同 catalog 之间可以重复，**跨场景关联必须使用 `(catalog_id, target_id)`**，不能凭 `satnum` 合并或映射真实卫星。
3. 通过 SGP4 传播与地站几何计算构建完整观测窗口，使用公共规划核心的 30 秒时间网格。catalog 保存完整窗口；各场景按“日×站点”分层确定性选取每目标最多 12 个窗口，保存 `pool_windows.npz` 和 `catalog_window_id` 映射。少于 12 个窗口的目标保留现有窗口；没有窗口的目标继续保留在输入和质量分母中。不能把抽样后的池写成该场景所有可见机会。
4. **特征和教师均基于保留的候选池**。每个候选表示“一个目标在某站点的池内窗口观测某种时长”，时长为 4–8 格，即 120、150、180、210、240 秒，并受窗口长度限制。开始时刻由放置器寻找。固定 3 轮价格协调后提取 20 维特征，再由本地规则和两遍贪心放置生成网格计划，不运行局部搜索。3 轮不代表价格收敛，保留的 `best_mu` 可能仍为零。“价格”是站点时间资源的竞争代价，不是货币；特征不能包含最终教师选择标签。
5. 从教师实际网格状态的窗口、时长和任务顺序构造选择标签，再以 `near=False` 进行整数秒精修。该精修不补入附近新窗口，并检查任务目标及站点身份保持一致；起止及持续时间可以改变。独立校验引发的非法任务删除另记修复记录。网格选择标签始终与发布的网格计划对齐，不能从精修后的秒数反推替换。
6. 分别独立校验网格和最终计划，记录状态、质量和阶段时间。固定修复策略最多删除一次校验指出的非法任务，然后重新完整校验，并保留原计划、原报告与修复后报告。结构或系统级错误停止处理；无非空合法计划则记为失败，不静默换种子或用空计划掩盖错误。

轨道参数范围如下。“平均半长轴高度”是平均半长轴减去 6378.135 km，并非每个传播时刻的真实离地高度；这些分布是设计假设，没有拟合真实卫星群体。

| 类别 | 平均半长轴高度/km | 偏心率 | 名义倾角/° | B* |
|---|---:|---:|---:|---:|
| LEO | 550–1600 | 0–0.012 | 20–110 | 1e-6–3e-5 |
| MEO | 8000–24000 | 0–0.08 | 20–80 | 0 |
| GEO-like | 35000–36500 | 0–0.025 | 0–20 | 0 |

各连续参数在给定区间均匀抽样，升交点赤经、近地点幅角和平近点角各在 0°–360° 抽样，平均要素计算的近地点要求至少 450 km。类别比例是独立抽样概率，实际 catalog 比例存在随机波动；偏移组仅按前述规则改变类别概率和 LEO 倾角。B* 为弱阻力建模假设，平均运动的一、二阶导数置零。

十个虚构光学站位于 [`catalog.py`](../../obsplan/training_data/catalog.py) 中的陆地区域锚点附近：经纬度各独立扰动最多 0.08°、站高扰动最多 30 m。它们不对应真实设备及可用性。四种变体的随机源为 `catalog_seed + 100000 × (variant + 1)`：

| 变体 | 站点 | 优先级设置 |
|---|---|---|
| `balanced` | 全部 10 站 | 低/中/高按 50%/30%/20% 概率抽样。 |
| `high_priority_dense` | 全部 10 站 | 低/中/高按 20%/30%/50% 概率抽样。 |
| `scarce_targets_prioritized` | 全部 10 站 | 依据完整窗口数从少到多排序，同数随机破平局；无窗口目标排在有窗口目标之后。排序前 20% 为高、接着 30% 为中，其余为低。 |
| `half_station_capacity` | 固定种子选择 5 站 | 低/中/高按 50%/30%/20% 概率抽样；保留原十站索引映射。 |

目标及站点数据为原创合成；不并入此次调查的 Hugging Face 数据集。太阳位置计算可能使用既有天文星历，运行依赖及指纹应与生成清单一起记录。[外部来源调查与方法依据](SOURCES.md)

## 规则与单位

| 内容 | 本版本采用的口径 |
|---|---|
| 时间 | UTC；任务开始时间相对场景起点，单位秒；最终计划为整数秒 |
| 仰角 | 整段观测处于 10°–85° 范围内 |
| 站点夜间 | 观测期间站点太阳高度角低于 −6° |
| 目标受照 | 观测期间目标不在球形地球本影内；沿用公共 Skyfield 参考口径 |
| 观测时长 | 生成器使用 120–240 秒；240 秒是计分饱和点，不将其扩写为比赛禁止更长任务的条款 |
| 站点资源 | 每站同时至多一个任务，相邻任务保留 30 秒切换时间 |
| 重访 | 同一目标跨站统一计算；前次观测结束至下次开始至少 48 小时 |
| 优先级 | 高/中/低对应 5/3/2 分 |
| 天气、月光与亮度 | 本版本不建模云层、月光规避、目标亮度或仪器探测阈值。 |

完整规则及开发假设见仓库[规则口径](../../../规则口径.md)。规划器的安全余量、传播异常检查及窗口缓存配置以发布配置为准。1 秒离散采样是数值复核，不是连续时间解析证明，也不代表真实设备一定能够执行。

## 20 维候选特征

特征列顺序严格对应 [`obsplan.famou_h_eval.FEATURES`](../../obsplan/famou_h_eval.py)，**窗口数量、稀缺度、冲突和价格等均相对于保留的候选池计算**。时间格长度是 30 秒；`duration_cells` 为观测时长的格数，资源占用还包含切换处理，不能将所有 `cells` 字段直接当作秒。特征生成函数先将数值保留到小数点后 4 位，本地规则以 float64 计算，发布特征压缩存为 float32；后者适合训练，不承诺逐位复现原规则浮点运算。

| 序号 | 列名 | 解释 |
|---:|---|---|
| 0 | `priority` | 目标优先级原始分，取 2、3 或 5。 |
| 1 | `duration_cells` | 候选观测持续格数；乘以 30 才是观测秒数。 |
| 2 | `task_score` | 该时长的一次观测原始分，不包含首次覆盖价值。 |
| 3 | `cover_value` | 首次覆盖价值换算到任务得分尺度的常数 `vc / vs`。 |
| 4 | `price_cost` | 在窗口内放置该时长所需的最低资源价格成本，换算到任务得分尺度。 |
| 5 | `price_per_cell` | `price_cost / (duration_cells + 1)`，对应公共放置器的占用格计价。 |
| 6 | `window_cells` | 窗口末端与起端的格索引之差。 |
| 7 | `slack_cells` | `window_cells - duration_cells`，表示窗口相对候选时长的余量。 |
| 8 | `target_windows` | 目标在该场景保留池内的窗口数，不是完整几何窗口数。 |
| 9 | `scarcity` | `1 / (1 + remaining)`；`remaining` 为当前窗口结束后才开始的同目标窗口数。 |
| 10 | `urgency` | `1 / (1 + next48)`；`next48` 为当前窗口结束后 48 小时内开始的同目标窗口数。 |
| 11 | `conflict` | 窗口内平均候选窗口负载，再除以场景中的最大平均负载；是静态拥挤度代理。 |
| 12 | `night_pos` | 窗口中点在所属夜间区段的相对位置，约 0/1 对应黄昏/黎明，0.5 对应区段中部。 |
| 13 | `time_frac` | 窗口起点格索引除以场景采样格数，表示规划期内的相对时间。 |
| 14 | `max_obs` | 公共问题对象对该目标给出的观测次数上限，不是已执行次数。 |
| 15 | `sub_pick` | 按当前价格独立求解该目标时，其选择的观测是否落在当前站点窗口内；0/1。 |
| 16 | `sub_pick_same_duration` | 上述独立选择是否同时与当前候选时长相同；0/1。 |
| 17 | `sub_count` | 当前价格下，该目标独立子问题选择的观测次数。 |
| 18 | `target_dual` | 当前价格下该目标子问题的价值，经 `vs` 换算到任务得分尺度；不等于合法全局计划得分。 |
| 19 | `window_demand` | 所有目标的独立子问题请求在当前窗口内形成的平均资源需求。 |

其中价格和子问题特征需要实际计算。若训练后的模型仍使用这些特征，端到端评测必须计入该预处理时间；不能仅报告神经网络前向传播时间。特征是规划前的一次快照，未逐步编码“哪些任务已经占用站点、哪些目标已经观测”。

## 标签、计划及文件语义

发布物区分以下内容；加载器以顶层 `manifest.json` 的 `scenes` 列表为准，不依赖硬编码的场景目录名。

| 内容 | 语义及使用边界 |
|---|---|
| catalog 与场景配置 | 重现轨道、站点、优先级、时间范围、随机种子、规则和划分；同 catalog 只允许一个划分。 |
| 完整窗口与保留窗口 | catalog 保存完整几何窗口；scene 的 `pool_windows.npz` 保存保留窗口及 `catalog_window_id`。`actions.npz` 的 `candidate_window` 指向 **pool**，不得直接索引 catalog 完整窗口。 |
| 候选特征 | 上表 20 维输入；标准化统计只允许在 train 上拟合，再用于 validation/test。 |
| 网格选择标签 | 1 表示教师网格计划选择该候选，0 表示该教师未选择。**0 不代表物理非法，也不代表其他调度中没有价值。** |
| 网格计划 | 网格教师实际放置的任务及开始时间，用于复核行标签与教师选择的一致性。 |
| 最终秒精修计划 | 教师在保留候选池内生成的计划经秒精修后的输出，用于覆盖、原始得分、质量与合法性评测；不直接倒推覆盖原网格行标签。 |
| 校验与运行记录 | 验证步长、结构与几何错误、运行状态、阶段耗时、配置和代码指纹；保留失败/超时。 |
| 资产清单 | 发布分片 URL、字节数、SHA-256、场景列表及划分；下载后先校验完整性。 |

每个场景的 `actions.npz` 使用不依赖 pickle 的 NumPy 数组。令 `C` 为候选数、`T` 为发布网格计划中的任务数：

| 字段 | 类型与形状 | 语义 |
|---|---|---|
| `features` | float32，`[C, 20]` | 上述静态候选特征。 |
| `candidate_window` | int32，`[C]` | `pool_windows.npz` 的窗口索引。 |
| `candidate_duration_cells` | int16，`[C]` | 候选观测格数，4–8。 |
| `rule_score_uncovered` | float32，`[C]` | 本地规则输出的目标未覆盖时分数。 |
| `rule_score_covered` | float32，`[C]` | 目标已覆盖时的原始规则分；公共恢复器实际使用 `min(uncovered, covered)`。 |
| `grid_selected` | bool，`[C]` | 是否至少被教师选择一次。 |
| `grid_selected_count` | int32，`[C]` | 该候选实际被放置的次数；长窗口中可能多次放置。 |
| `grid_selection_rank` | int32，`[C]` | 首次放置在网格计划中的零基任务顺序；未选中为 −1。 |
| `grid_start_s` | int32，`[C]` | 首次放置相对场景起点的秒数；未选中为 −1。 |
| `grid_duration_s` | int32，`[C]` | 首次放置的观测秒数；未选中为 −1。 |
| `grid_task_candidate` | int32，`[T]` | 每条网格任务对应的候选 ID，保留重复选择；长度是任务数，不能按候选行切片。 |

标签直接对应教师网格状态中的窗口/时长，而非依据时间近似匹配。候选级 rank/start/duration 只描述首次放置；要恢复全部任务，应同时读取网格计划及 `grid_task_candidate`。`grid_selected_count.sum()` 等于 `T`，`grid_selected` 等价于 `grid_selected_count > 0`，候选首次 rank 在存在重复放置时不一定连续。

`grid_plan.npz` 和 `plan.npz` 都包含 `station`（int16）、`target`、`start_s`、`dur_s`、`candidate_id`、`source_grid_row`（其余均 int32），各数组长度为该文件的任务数。`candidate_id` 指向 `actions.npz`；精修后的时长可以不再等于原候选格数×30。**`source_grid_row` 指向删除修复前的原始教师插入顺序，不是发布后网格计划的行号。** 网格计划和精修计划分别独立校验，也可能分别删去不同任务，应按 `source_grid_row` 关联，不能假设两文件同一行总是同一任务。相对地，`grid_selection_rank` 已按发布后的 `grid_plan.npz` 对齐。完整类型、数组维度和关联规则见 [schema.json](schema.json)。

原生输入由 `write_native_input` 导出 `轨道.txt`、`站址.txt` 和低/中/高优先级清单，可供共同读取器重新构建问题。完整 TLE 和 catalog 窗口允许后续研究重新扩池；扩池后的特征和标签必须重新生成，并标明新版本，不能沿用本版本教师选择标签宣称全窗口结果。

加载示例，假设 Release 分片已经校验并解压到包含 `manifest.json` 的目录：

```python
from obsplan.training_data.loader import DatasetReader

reader = DatasetReader("./extracted-dataset")
normalizer = reader.fit_normalizer()  # 扫描全部 train 行；不读取 test 拟合统计
for epoch in range(10):
    for batch in reader.iter_batches(
        "train", batch_size=4096, normalizer=normalizer,
        shuffle=True, seed=2026 + epoch,
    ):
        x = batch["features"]           # [B, 20]，可用 torch.from_numpy 转成张量
        y = batch["grid_selected"]      # 教师选择倾向，不能用作合法动作掩码
        scene_id = batch["scene_id"]
        candidate_id = batch["candidate_id"]  # actions.npz 中的原始候选行号
        # model training step ...
```

加载器每次载入一个压缩场景到内存，再在该场景内切批，批次不跨场景；因此无需把整个语料同时放入内存。训练建议 `shuffle=True`，它只改变指定 split 中的场景顺序和场景内候选顺序，各候选字段同步重排；默认关闭以兼容顺序读取。shuffle 后 `row_offset` 是本次重排顺序的偏移，不是原始候选行号；应以 `candidate_id` 恢复原行号。任务级 `grid_task_candidate` 不进入候选批次，完整映射使用 `iter_scenes()` 读取。

标准化均值和总体标准差只在 train 拟合，常量列的缩放系数设为 1；参数附训练清单指纹，用于拒绝误配。命令行 `--smoke` 仍会先扫描全部 train 拟合标准化，随后每个划分只读取一个批次，不应把这称为完整测试集评测。Git 内的约 1.74 MB 预览包含 200 目标 catalog 的 4 个 train 场景，不含 validation/test，只用于字段和接口演示。

## 可以训练什么，以及暂时缺什么

- **MLP 候选排序或选择倾向预测。** 每个候选用 20 维特征作为输入，学习教师的选择倾向；输出交给原来的合法放置器。由于未选中候选很多且常有可替代方案，应报告正类精确率、召回率或排序质量，同时回到完整场景比较最终计划，不能只看总体分类准确率。
- **离线模仿学习。** 可以模仿本轮教师在短表候选中的取舍。教师仅采用每目标最多 12 窗口、3 轮价格预处理与本地规则，不保证等于全窗口、更高预算 H+ 或融合方案，更不保证是全局最优。网络模仿得好不等于超过教师。
- **强化学习的实例输入。** 轨道、站点、窗口和规则可以用于初始化环境；本版本不是完整 `(state, action, reward, next_state)` 转移数据集，也不提供经过验证的奖励模型或参考策略模型。
- **Transformer 或 MCTS 的后续输入基础。** 可用候选关系构建集合、图或序列，但仍需额外实现动态资源状态、动作索引、合法动作掩码、状态转移与终止条件。MCTS 不是仅给静态行特征就能运行；其搜索模拟必须遵守共同约束。

建议首个学习基线使用小型 MLP，并与相同候选池、预处理和放置器下的本地规则、人工贪心比较。短表筛选可能删除优质观测机会，神经网络仅重排保留候选无法找回这些机会；扩池实验应同时记录标签成本和最终计划收益。采用测试集评价前固定超参数，不根据 test 表现重新挑分布或删掉困难场景。分开报告同分布测试和预指定 `high_leo_shift` 组；不能仅凭 catalog 划分宣称对真实任务普遍泛化。

本地教师的排序规则此前已在原赛题全量实例上演化和评估，来源记录保存在 `obsplan/evolved/recover_rule.py`。因此，后续回到原赛题比较网络与教师时，应披露这项历史；原赛题不能自动称为对整个方法开发过程完全未见的测试集。本次新生成 catalog 的隔离解决的是合成训练、验证、测试之间的直接轨道复用问题。

## 质量、速度与验收记录

每份合法最终计划至少报告目标数 `N`、不同目标覆盖数 `C`、原始累计观测分 `S`、内部质量 `Q`，以及输入/窗口预处理、完整教师求解、独立校验、端到端时间。合成场景的归一化分母必须使用本场景的 `N` 与 `sumP`，不能写死赛题原始实例的 10000 和 30062。

单任务原始分为 `P × [0.6 + 0.4 × (d − 120) / 120]`，其中 `P` 是优先级分、`d` 为 120–240 秒的时长。`S` 累加所有合法观测，重复观测可增加 `S`，但不重复增加 `C`。内部质量为：

```text
Q = 0.5 × C / N + 0.5 × S / sumP
```

这不是比赛官方分数。`sumP` 是所有目标各满分观测一次的分值和，允许重访时 `Q` 不保证小于等于 1。数据生产耗时用于说明标签成本；没有同硬件、供电、线程、缓存条件的重复对照时，不将本次时间数字写成算法性能排名。

发布验收要求包含：catalog 交集为空、候选特征维度和数值有限性、候选—标签—网格计划对应一致、参数与传播合理性检查、最终计划的整数秒结构约束、全部最终计划的独立 1 秒几何复核，以及分片哈希校验。必须分别统计“完成”和“通过”，避免将存在校验文件误写成校验通过。

正式并行生产与之前校准/中断记录分开解释：两次 200 目标 pilot 均完成四个变体，每次合计 2,175 条最终任务；此前串行试跑完成 6 个场景，第 7 个场景发生 `KeyboardInterrupt`，保留了该次试跑。以上都不计入正式 120 场景的完成数量，也不能据此写正式数据“零失败”。正式构建结果与全部失败/超时统计以最终审计为准。并行场景的耗时总和可以大于整体经过时间，不得将两者混写成端到端等待时间。
