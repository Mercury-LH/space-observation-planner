# 给队友及其 AI 助手的工作约定

本目录实现的是**空间目标观测任务规划**，不是“面向全球覆盖与区域重访的星座构型优化设计”。主说明见 `docs/自动评测与协作.md`。开始改代码前先读该文档和 `docs/规则口径.md`；规则来源与未确认假设必须保留。

## 规则与证据

- 标准比较期为 **2026-08-01 00:00:00 至 2026-08-07 00:00:00 UTC**，10000 个目标、10 个站。30 秒是构造候选的时间网格，不是地表网格；最终计划按整数秒精修。
- 不把其他赛题的“直接 Access、沿迹视场 0.81°”公告加到本题模型。
- 保留仰角上下限、站点夜间、目标受照、最短观测、切换、跨站同目标重复间隔等硬约束。重复间隔从前一次**结束**到下一次开始计算。
- `combined` 和新时间加权分都是团队内部指标。`sumP` 只相当于全部目标各满分观测一次；因为允许重复观测，综合值理论上可能超过 1，时间加权分也不是官方百分制成绩。
- 不把离散采样校验说成解析连续时间证明，不把有限配置搜索说成全局最优，不把固定实例上的伐谋演化收益说成泛化结论。

## 统一接口与迭代

- 算法适配入口是 `obsplan.portfolio.solve(pb, spec, progress=None) -> (Schedule, info)`。新算法可以做成同签名的 `module:function` 插件，用统一 benchmark 运行。
- 算法返回完整 `Schedule`，站点和目标用 `pb.ds` 的零基索引；开始时间相对规划起点，单位秒，开始和持续时间必须是有限整数秒。不得返回分数代替计划。
- 数据读取、窗口生成、计分、独立校验及导出由公共代码负责。不要在自己的算法中复制一套规则或修改公共评测器来提高成绩。
- 用 `obsplan.benchmark` 跑对照。保留全部运行、失败和超时；不只挑最好一次。不得复用预先生成的 E/G/H 计划却漏记生成时间。
- 时间加权推荐必须同时提供覆盖、原始观测分、综合值、求解时间、校验时间和端到端时间。固定权重和时间尺度后再看结果，不根据当前选手中最慢的一项动态归一化。
- 正式对照串行运行，记录数据/配置/代码指纹、依赖版本、硬件和线程数；窗口缓存和编译预热口径要相同。换机器、代码、数据或规则后重新跑基准。
- 多线程 CP-SAT 的限时搜索可能有波动；最终推荐至少复跑一次，并报告范围。校验未执行、未完成或不通过的计划不能进入推荐排名。
- 修改求解器时补充能发现真实错误的测试；修改公共规则或校验时必须做回归。不要只验证自己构造的快乐路径。

## 伐谋和提交

- 默认 H+ **本地执行** `obsplan/evolved/recover_rule.py`，不会请求云端伐谋服务。自动评测不需要 API key。
- 继续演化规则是单独的 `integrations/famou_h*` / `scripts/famou_ctl.py` 工作流，会调用外部服务并消耗资源。不要为了跑 benchmark 自动创建实验。
- 候选生成代码需要审阅后才可加载。插件和候选都是执行代码，进程隔离并不等于安全沙箱。
- `outputs/`、`cache/`、完整计划、目标明细和凭据不提交。只提交可复现配置、摘要、测试和说明；凭据不得硬编码、打印或写进 Git。
- 在自己的分支开发。提交前读 `git diff`、运行相关测试，核对待提交清单；不得覆盖队友的未提交文件或强制推送共享分支。
