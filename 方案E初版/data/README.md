# 本机私有数据

仓库不包含赛事原始数据。拿到主办方提供的数据后，在本方案目录中按以下结构放置，保留原始文件内容：

```text
方案E初版/
  data/
    README.md
    开运联合/
      数据/
        轨道.txt
        站址.txt
      优先级/
        高优先级目标.txt
        中优先级目标.txt
        低优先级目标.txt
```

五份示例配置的 `data_root` 均为 `data/开运联合`，相对路径从 `方案E初版/` 解析。如果数据已经存放在别处，可将要使用的配置中 `data_root` 改为该目录在本机的绝对路径；不要把个人绝对路径提交到 Git。

程序仅要求上述五份 TXT，说明 DOCX 不是运行时输入。加载时严格检查 TLE、优先级匹配和站点字段，数据错误会停止运行，不会静默跳过记录。单元测试使用合成输入，不需要此私有目录。

在本方案目录安装环境后，先执行：

```bash
.venv/bin/python -m space_planner audit --config configs/subset_200_1day.json
```

私有数据、生成的窗口、观测计划和缓存只留在本机。历史实验摘要随方案发布，历史 `outputs/` 目录不在仓库中。请用本机数据重新运行配置生成新的 `manifest.json` 和 `windows.json`，再运行计划复核或伐谋评测；旧机器上的 manifest 可能记录不可用的绝对路径。
