# 方案 E 运行手册

面向企业赛题第四题「面向空间目标持续监测的 AI 自主观测任务规划与目标状态分析」的代码仓库。

项目目标是在有限地面观测资源下，为空间目标生成满足约束的观测计划，并根据任务和资源状态变化进行动态重规划。

## 当前状态

已完成第一阶段：真实数据审计、分块轨道/可见窗口计算、独立计划校验、贪心组合、ALNS 和局部 CP 修复诊断均可运行。10,000 目标、10 站、6 天实测覆盖全部目标，当前开发假设下得分距窗口模型乐观上界最多 1.6 分；暂缓交互模型训练。子集、全量、边界审计、耗时、内存与方法取舍见 [第一阶段实验报告](research/2026-10-20-stage1-results.md)。当前没有已训练的交互收益模型，也没有证明方法新颖性。

输入格式、物理约束和评分指标以主办方最终确认规则为准。已核对的原材料、数量、历元与待确认项见 [数据审计](research/2026-10-20-data-audit.md)，坐标、事件细化、缓存与可靠性边界见 [几何方法说明](research/2026-10-20-geometry-method.md)，AI 候选路线见 [研究记录](research/2026-10-19-ai-innovation-route.md)。原始材料保留在被 Git 忽略的 `data/开运联合`（或配置指定的私有目录），不会上传。

本手册与 [初版入口](../README.md) 配套。历史实验输出没有随 Git 发布，请先配置自己的私有数据，重新生成本机运行记录。

## 安装与测试

百度伐谋混合云使用独立的 Python 3.12 环境，配置、评测接口与命令见
[伐谋接入说明](../integrations/famou/README.md)。云端迭代候选算法，本地保留数据与独立评测。
已完成 10 轮实际试跑，选中候选在 300 目标拥挤开发场景覆盖 48 个目标，
在未参与云端评分的 1000 目标场景覆盖 212 个；记录和适用范围见
[伐谋接入验证报告](research/2026-10-20-famou-integration.md)。

项目声明 Python 3.9 或以上；已验证环境为 macOS，候选隔离执行要求 macOS。直接依赖写在 `pyproject.toml`；`requirements-lock.txt` 记录本次 CPython 3.9、macOS arm64 实验环境的完整依赖版本。在兼容环境复现时，在本方案目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
git diff --check
```

测试使用合成输入；真实数据实验由下面的命令显式运行。其他平台可能没有锁定版本对应的二进制包，若需调整依赖，应保留新环境版本并分别报告，不能视作同一软件环境。

## 本地运行

```bash
# 只做真实数据加载和审计
.venv/bin/python -m space_planner audit --config configs/subset_200_1day.json

# 200个固定随机目标、10站、1天；贪心与3个ALNS随机种子
.venv/bin/python -m space_planner run --config configs/subset_200_1day.json

# 容量竞争实例：1000个固定随机目标、3站、3小时
.venv/bin/python -m space_planner benchmark --config configs/congested_1000_3h.json

# 全量10000目标、10站、6天：先只测窗口计算
.venv/bin/python -m space_planner windows --config configs/full_10000_6days.json

# 确认窗口性能后再运行全规模调度基线
.venv/bin/python -m space_planner benchmark --config configs/full_10000_6days.json
```

也可以使用安装后的 `.venv/bin/space-plan` 入口。`--output outputs/指定目录` 指定一个不存在或空的输出目录；默认每次建立带 UTC 时间戳的新目录，不覆盖上次结果。相对配置路径中的 `data_root`、缓存目录与输出基础目录始终相对本方案目录解析。

`audit` 不需要时间范围。其他命令必须显式给 `start_utc`（包含 `Z` 或时区偏移）及 `days` 或 `horizon_s`。示例使用 `2026-08-04T00:00:00Z`，仅是靠近 TLE 历元的开发选择，不是主办方确认日期；不会根据今天日期推到 10 月。

`target_limit` 按 `selection_seed` 从全部目标中随机抽样，再按编号排序；它不取原文件前 N 行。可改用 `target_ids` 指定编号，两者互斥。省略两者表示全部目标。`station_ids` 可选择站点；省略表示全部。

## 输出与复现

每次实验保存在被 Git 忽略的 `outputs/`，包含：

- `manifest.json`：解析后配置及哈希、输入 SHA256、实际选择编号、源代码 SHA256、Git 状态、依赖版本、平台、墙钟时间、进程峰值 RSS；未提交代码也可追溯版本。
- `audit.json`：数据格式、编号匹配、校验和、历元和轨道尺度。
- `windows.json`：UTC 起点、相对起点的秒数窗口、计算统计和缓存信息。
- `plans/greedy.json` 与 `plans/alns_seed_*.json`：任务列表、指标、独立校验、求解和校验耗时；贪心记录各策略实际耗时和完成度，ALNS 记录迭代轨迹与算子权重。
- `summary.json`：覆盖数/比例、观测累计得分、每目标取最佳一次的得分、可观测目标覆盖率、按优先级覆盖、资源占用及运行统计。

指标还给出“忽略站间任务竞争、每个目标取最长可见窗口”的乐观覆盖和单次得分上界。它只针对当前数值窗口模型；不能据此证明连续物理问题的全局最优。重复观测开启时，累计观测得分上界留空，覆盖及每目标最佳一次得分的上界仍可报告。

所有计划的 `start/end` 均为相对于配置 UTC 起点的秒数。默认独立校验器重新调用传播/几何，检查观测全程仰角上下界及站冲突等约束；`--skip-geometry` 仅适用于结构调试，输出会明确记录 `geometry_checked=false`。任何计划校验失败会保留结果并返回非零退出码。窗口提取和独立校验都是带局部极值细化的数值方法，不宣称形式化完备证明。

贪心组合按顺序执行各策略，共享一个 `greedy_time_limit_s` 软预算；预算耗尽时后续策略可能没有运行，应查看 `plans/greedy.json` 的 `diagnostics.strategy_runs`、实际启动数与完成数。ALNS 各种子共享保存的贪心初始计划；算法耗时与共同预处理、独立校验分开报告。`alns_iterations` 固定迭代上限，`alns_time_limit_s` 提供可选软墙钟上限，两者谁先到就停止。墙钟截断会造成不同机器上的迭代数不同；追求算法序列复现时可将墙钟上限设为 `null`。峰值 RSS 是进程累计高水位，不是算法独占内存。

窗口扫描步长敏感性和 85° 上界诊断使用 [audit_geometry.py](../scripts/audit_geometry.py)：

```bash
.venv/bin/python scripts/audit_geometry.py \
  --config configs/subset_200_1day.json \
  --output outputs/geometry_audit_200_1day.json --fine-step 15
```

该审计比较同一实例的 30/15 秒事件搜索结果及取消上界后的窗口差异；一次子集一致不等于证明全规模无漏检。完整物理假设和数值限制见 [几何方法说明](research/2026-10-20-geometry-method.md)。

## 显式开发假设

默认每目标最多观测一次，按“覆盖优先、得分次之”进行字典序优化。120 秒得 60%、240 秒及以上得 100%；默认 `score_mode="step"` 对中间时长保守保持 60%，`"linear"` 是可选但未获官方确认的假设。重复间隔默认 `null`，不添加 48 小时规则；没有太阳高度 −6 度过滤。

已确认优先级权重 5/3/2、切换 30 秒、同站互斥、仰角 10–85 度；完整解释见数据审计。不同配置的实验不能当作同一官方成绩比较。产品/展示、动态状态闭环和最终程序中的任务相关 AI 能力仍需后续完成；仅用 AI 编写代码不构成最后一项。

## 联合收益诊断

`probe` 命令先建立窗口与贪心计划，再对显式给定的两个站点时间块分别与联合修复。配置可添加：

```json
"probe": {
  "block_pairs": [{"1": [0, 1800], "5": [0, 1800]}],
  "time_limit_s": 2,
  "max_options": 400,
  "seed": 0,
  "metric": "coverage"
}
```

```bash
.venv/bin/python -m space_planner probe --config configs/包含probe字段的配置.json
```

对已保存的真实实例自动抽样时间块，可复用运行目录：

```bash
.venv/bin/python scripts/probe_real.py \
  --config configs/subset_200_1day.json \
  --windows outputs/运行目录/windows.json \
  --plan outputs/运行目录/plans/alns_seed_0.json \
  --output outputs/probes/subset200.json --samples 12 --seed 0
```

输出 `probe.json` 保留局部求解下界/上界、限制和交互收益不确定性。受限候选集上的正交互不等于整体最优提升，更不证明训练模型有效；模型路线需要与交换链、中性移动、同预算 ALNS 和直接总收益预测等基线继续比较。
