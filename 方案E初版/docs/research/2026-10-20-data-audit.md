## 范围与证据来源

本次直接读取 `data/开运联合` 中的 `说明.docx`、`开运联合：面向空间目标持续监测的AI自主观测任务规划与目标状态分析.docx`、`数据/轨道.txt`、`数据/站址.txt` 和三个优先级文件，未以旧目录副本替代。DOCX 通过 ZIP/XML 只读提取正文；没有上传材料，也没有把原始目标记录写入测试或仓库文档。文档锁文件不是证据源。

数据加载入口为 `space_planner.data.load_dataset(root)`；传入的 `root` 应是上述 `开运联合` 目录本身。返回的 `Dataset.audit` 可直接写成 JSON，包含输入文件哈希、异常、数量、历元和轨道尺度。加载器不修改源文件。

## 尚不能写成官方规则的事项

- 没有找到 48 小时重复间隔、覆盖率/观测得分各占 50%、120–240 秒线性得分、太阳高度低于 −6 度或固定 10 月起始日期。
- “前后一共 6 天”没有明确统一起始 UTC、前后各几天、是否以某个目标历元或整个数据集代表历元居中。必须由运行参数给定区间，靠近实际历元的试验区间是开发选择。
- 重复观测的分数是否累计、同目标跨站同时观测是否合法、是否每目标最多一次、相邻同目标任务能否拼接累计时长，均未在本次文件中给出机器判定规则。必须显式配置/标注开发假设，避免把自行去重或合并后的分数称为官方最终分。
- 站址表只给经度、纬度、海拔，未声明大地坐标基准、折射模型、地球定向参数或光学照明条件。采用 WGS84、几何仰角等属于实现选择；相应近似应留在实验说明中。
- 历史观测状态、动态事件及状态更新字段在题目文档中提出，但本次实际 TXT 文件没有这些字段。合成事件必须标注为开发场景。
- `说明.docx` 给出计算结果 40%、产品体验 30%、算法效率 30%、额外最多 10%；题目文档给出硬约束/重点目标/动态重规划/效率稳定性/程序说明 25/25/25/15/10。文件之间没有明确说明二者关系或优先版本。保留两套来源，暂不自行合成统一加权成绩。

第一阶段应分别报告目标覆盖、按优先级权重的观测得分、各优先级覆盖、资源占用、约束违规、运行时间和求解预算；“总分”只允许表示写明公式的开发目标。

| 项目 | 结果 |
| --- | --- |
| 轨道格式 | 10,000 个三行记录：名称行 `0 …` 加标准 TLE 第 1/2 行；不是文件说明泛称的 AOE 表 |
| TLE 轨道行 | 20,000 行，均长 69 字符；全部校验和通过 |
| 目标编号 | 10,000 个唯一编号；108 个 Alpha5 |
| 优先级分组 | 高 2,024、中 3,990、低 3,986 |
| 优先级完整性 | 无组内重复、组间重叠、缺漏或额外编号 |
| 最早历元 UTC | 2026-08-02 16:00:01.999584 |
| 最晚历元 UTC | 2026-08-04 15:52:26.254272 |
| 周期 min / median / max | 87.5748 / 97.9066 / 7470.6474 分钟 |
| 周期 ≤128 / (128,1200] / >1200 分钟 | 8,502 / 481 / 1,017 个；此为尺度分箱，不是正式轨道分类 |
| 偏心率 min / median / max | 0.0000023 / 0.0004782 / 0.6553086 |
| 轨道倾角 min / median / max | 0.0013 / 66.02875 / 144.6327 度 |
| 地面站 | 10 个，站号保留为字符串 `"1"`–`"10"` |
| 各自历元 SGP4 检查 | 10,000 个目标返回码全部为 0；SGP4 `satnum` 与加载器编号全部一致 |

周期按 `1440 / TLE mean_motion_rev_per_day` 计算，是 TLE 平均运动对应的尺度，而非逐点数值测出的实际周期。最大周期约 5.19 天，不能把全部目标当作低轨快速周期对象。各自历元传播成功也不保证整个 6 天窗口均传播成功，后续几何计算必须继续检查每个传播返回码。

在“每个目标计一次且均取得满分”的开发口径下，全部目标权重和为 30,062。这个值仅用于归一化分母核对，不等于主办方已确定的重复观测计分规则。

经度原表混用负数和 0–360 度；加载器保留审计中的原值并转换到 `[-180,180)`：

| 站号 | 原经度 | 规范化经度 |
| --- | --- | --- |
| 8 | 290.458202 | −69.541798 |
| 9 | 249.126539 | −110.873461 |
| 10 | 358.445658 | −1.554342 |

首个站号使用全角冒号，解析器兼容全角冒号及逗号。三个优先级文件均是单行逗号分隔；不能按逐行整数读取。Alpha5 遵循 A=10、跳过 I/O 的字母表：例如 A0052 对应十进制 100052，不能删掉字母或与优先级编号直接字符串比较。

## 加载器行为及边界

- 默认严格拒绝校验和错误；实际文件全部通过，没有理由静默“修复”或忽略它。
- 检查 TLE 固定宽度、字段分隔、双行编号一致、日期范围、角度范围、数值字段及正平均运动。接受带 `0 ` 名称行的三行记录，也接受无名称的两行记录。
- 检查目标/站号重复、优先级非整数、优先级重复、优先级与轨道双向缺漏。失败抛 `DataAuditError`，其 `.audit` 包含结构化错误，不返回部分可用数据。
- 为支持合法小规模合成实例，不把“恰好 10,000/10”写死为普遍加载约束；实际数量始终进入审计。
- 实际数据的仰角上下界从站址文件读取。缺少限制行时使用显式 10/85 默认，并在审计中产生警告；未识别的站址内容直接拒绝。
- 本加载器校验输入格式和基本数值范围，不代替传播有效性、完整可见窗口计算或计划硬约束校验。
